# 代理技能如何比较

 人们经常问,如何 **代理技能** 有关其他两个“编码代理技能”的集合,他们听到的大多是: **超级力量** ( 杰西·文森特/欧布拉) 财务报告和财务报告 ** 马特·波考克的技能** 三者都是好的,分享了很多DNA,值得学习。这页是一张真实的地图,说明他们是如何的。 *形状* 不同,所以你可以选择一个适合你工作的方式, 或者借过所有三个。

> **TL; DR 数据** - 它们在不同的时刻优化。 **代理技能** 组织 *整个产品寿命周期* (定义、计划、建造、核查、审查、船舶) 与审查人,反合理化的警卫, 和一个在反转录 eval框架,检查技能 实际路线和行为。 **超级力量** 倾斜到 *自主性、推理性强* 使用亚剂运行, 严格的管道, 和工作树隔离。 ** 马特·波考克的技能**  为 a *尖锐、有见解 Claude Code 工具包*  从一位专家的日常工作流程中提炼出来,带有一个签名的"Grill me"审讯循环,无一是抽象的"最佳";这取决于你面前的工作.

## 这三个项目,按它们自己的条件

### 超级力量 (欧巴)

软件的全面开发 *方法* 以可堆肥技能为基础 赌注在 **自治和前述推理**,一个会场运行一个刻意的线性管道: Socratic集思广益,写一个日期的光谱并允许完全一个交接,详细计划被写成"一个品味差且没有上下文的热情的初级工程师"执行,然后由亚剂驱动执行,一个新鲜的副剂执行每个任务,任务审查员在关闭前在光谱遵守度和代码质量上都签下字,上面写着任何标记的固定环路,最后在最有能力的模型上进行全处审查. Git 工作树将平行工作隔离开来, `writing-skills` 应用技能 TDD (a) 证明文件本身:没有经过失败测试的熟练船只。

 它的长处是真实的:交出一个巨大的块,回到一个经过审查的结果,用强大的护栏来对付一个使这一过程合理化的代理人。 权衡是这一学科的反面。 覆盖面是狭窄的。 (这是一种内向的构建方法,而不是安全发射的生命周期), 单一的管道可以对小的变化感到沉重,而最近的方向是支付这一成本,比如,将大约两倍的速度和一半的符号合并到一个单一的任务审查员身上。 其社区所不断要求的,多代理团队执行的最响亮的东西还没有在盒子里。

**重播 :** <https://github.com/obra/superpowers>

###  马特·波考克的技能

 马特开源 Claude Code  他实际使用的技能, 和收藏 已经发展成一个宽广, 有意见的工具箱 在公共组织, 完成与可见 `in-progress/` 财务报告和财务报告 `deprecated/` 用来模拟技能所宣扬的学科的目录。重力中心不是 TDD,这是 **烧烤**:一个可重复使用的询问循环,一次问一个问题,将设计树的每一个分支解决依赖性按顺序走,每个问题给出一个推荐的答案,更喜欢读代码库而不是询问,在确认共同理解之前拒绝继续. `grill-me` 财务报告和财务报告 `grill-with-docs` 上面是薄薄的包层。 TDD 技艺也与众不同 令人愉快的异形 ("重构不是循环的一部分" 它属于代码审查),并且有故意将用户引荐的技能与模型引荐的技能区分开来,将代理语境视为稀缺的预算.

 它的长处是真实性和尖锐性:这就是一个非常好的工程船,而不是一个委员会提出的框架概念,而要求的刺激循环是真正极好的。 Claude Code 实际中第一 (表面可靠性粗略边缘),没有可捕捉回归的回旋录,以往的生命周期覆盖范围很薄,一些技能伴侣与个人设置的向导和跟踪者公约。 近期的工作正在通过问题跟踪器将单会场技能推向多会场协调。 (A. 执行中的进展 `wayfinder`).

**重播 :** <https://github.com/mattpocock/skills> · 相关: <https://github.com/mattpocock/agent-rules-books>

### 代理技能 (这个项目)

代理技能组织 **整个产品寿命周期**  作为技能,具有元技能 (`using-agent-skills`) 每一个技能都包含着一个 **共同合理化** 表格显示 (代理商的借口 跳过一步,每个被反驳) 财务报告和财务报告 **红旗**将一对一至生命周期阶段映射为斜线命令; `/build auto` (a) 一次通过一个经核准的整个计划; `/ship` 粉丝退出审查 **个人为** (`code-reviewer`, `security-auditor`, `test-engineer`, `web-performance-auditor`) ,然后将它们合并成一个 go/no-go.  它在每个阶段都设有人员检查站,运送7份参考核对表,包括一份 " 完成的定义 " ,并穿过大多数主要代理工具,在其中若干工具上安装一个单一命令。

较新的是什么,以及目前的差别点:a **三级eval框架**  第一级检查结构 第二级检查 每种技能的描述都包含着词汇的用户 并且没有两种技能在路由上相互碰撞 (确定性,运行在 CI), 以及第三级 代理真实执行的痕迹与每个技能的预期值相对应。今天,其他两艘轮船中,无论是哪艘船,都是在反转,全目录的测量中。 诚实的权衡方向是:代理技能比超级能力少一个有观点的“运行”,而三艘舰都还没有很好地解决持久的跨会内存问题。

## 真正的头对头:超能力与代理技能

Om Mishra 运行了控制实验, 相同的模型, 相同的回波, 相同的提示输入 Claude Code,只改变技能框架,并写下:

**["超能力对特工技能:更快的航运,更安全的理性"(英語:Superpowers vs Agent-Skills:Secretary Shipping, Safer Reasoning) 互联网档案馆的存檔,存档日期2014-03-02.](https://www.linkedin.com/pulse/superpowers-vs-agent-skills-faster-shipping-safer-reasoning-om-mishra-dzakf/)** 由奥姆·米什拉(Om Mishra)撰写

简要总结:

- **代理技能** 移动到代码更快 (~8分钟对~12分钟) 运行 **更多验证证** (7 vs 5,包括全套测试套房)。这一更广泛的验证遇到了兼容性问题。 *外部* 切换特性测试错过的即时特征。 **验证深度** 完成这个任务
- **超级力量** 投资更多 ** 前期建筑推理** 他仍然喜欢作为日常驱动者 不断演变的生产系统 和探索性工作 没有既定的模式可遵循。
- Token效率实际上完全相同;两者都曾重新规划过一次。

 它是一个开发者的单一任务实验,不是基准,而是核心取舍的具体例子: **广义的纪律性验证与沉重的前置推理**. 他自己的结论是诚实的:选择工具完成任务.

## 如何决定使用什么

A-a- glance 表格告诉您它们是如何形状的。 这是如何在实际中选择的 。

###  从你作品的形状开始

- ** 一个完整的特色,前对后?**  这是三个人中唯一一个通过安全、性能 以及每个阶段的检查点 将你带离目标, 所以没有任何东西能悄悄地跳过审查或飞行前
- ** 一个大而模糊的块 你想交出 并离开?** 超能力。它的管道和亚剂审查是用来运行很长一段时间的,并将已经经过审查的结果交还给Spec。
- **快速的、专注的日常循环, 特别是在代码之前得到要求?**  马特·波考克的技巧,烤圈是三人最尖锐的要求工具,工具包不要挡路.

### 轻点你真正关心的

- **覆盖范围** (安全、业绩、 CI/CD,可观察性,发射):代理技能是明确的选择;其他则有内倾的焦点.
- **长期自治**:超能力,通过设计.
- ** 关于小改动的低级仪式**: Pocock的工具包最轻; 代理技能提供中间齿轮 ( 一个小的更改可以直接跳转到 `/test` 财务报告和财务报告 `/review`); 超能力是过程最重的.
- ** 对技能本身发挥作用的信心**: 代理技能是repo中唯一一个有全目录的 evals , 因此描述或路由回归失败 CI 而不是像一个神秘的"为什么后来没有技能的火"。
- **讯问要求**: Pocock的烤肉是参考执行; 代理技能' `interview-me`  在精神上是接近的,并获得一种选择进入的合作模式。
- **平台传播**:代理技能和超能力几乎无处不在; Pocock最快乐的是在 Claude Code.
- ** 每一步都有一个人门,对决跑道**: 代理技能检查站默认; 超级大国故意最小化中途登机.

### 具体设想

- *"在合并前用认证,测试, 以及安全通行证 发出新的端点"* 代理技能 : `/spec` 改为: `/ship`安全审计员和测试工程师 最终都向外倾斜
- *"在一夜之间重修一个 gnarly子系统 并在早上审查它。"* 超能力:将计划交给它,让亚剂驱动的发展和任务审查员运行.
- *"我有一个模糊的主意,并一直让经纪人猜到要求".* Pocock's (英语). `grill-me` (或特务技能" `interview-me`)  在任何代码之前 下定决心
- *"Fix one clear bug, test -first". "Fix one clear bug, test* 任何一种; 达到你已经安装的最轻的。
- *"规范一队工程人员如何使用代理人员跨越回购".* 代理技能:相位命令,人物,和共享的核对表给一个团队一个共同的词汇,Evals保持自定义技能的诚实.
- *"破坏我自己的技能 并知道他们触发正确。"* 并且为那些不能被合理化的人 借用超能力压力测试的纪律

### 独唱队对战队

 对于独奏开发者来说,品味和动力胜利:选择一个默认匹配您已经工作的方式,而最低的仪式选择往往是最常用的选择。 对于一个团队来说,微积分会转向共享的结构和护栏,您可以执行:命名阶段、审查人、核对表和失败的保温器 CI 才有五个人 (及其代理人)  在同一个标准上,而不是在五个私人工作流程上凝聚在一起。这就是情境代理技能的构建,尽管一个团队绝对可以采用Superpowers的检讨纪律或Pocock的烤圈。

### 共同的疆界 ( 三者皆为真)

 这些都没有解决 **持久的跨会话内存**  然而,一个特工在一次会面中学到的东西 很少带入下一场会面中。这三人都在盘旋着 (学习文件、移交文物、跟踪器支持的规划地图) 如果这是你的瓶颈,你知道你处于今天任何一艘飞船的边缘,并期望自己现在缝上一部分。

## 结合它们

 你不必单独选择,但要小心配合。 Markdown 技能,不是跑步时间,所以选樱桃 *个人* 技艺很好:拉进Pocock的 `grill-me`,一个超能力隔离模式,或者您主设置旁边的特定检查表。

 不起作用的是 运行其中两个 作为你的 **活动路由器同时运行**。堆叠的元技能争夺命令名称 (`/tdd` 定义在两个位置),在路由逻辑上进行竞争,并拉入不同的 TDD 哲学,所以你得到的是不可预测的行为,而不是两者中最好的行为。选择一个框架作为主要路由器,然后从其他人那里借一个la carte。
